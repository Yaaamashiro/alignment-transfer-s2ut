# S2UT metric audit and history migration

## Finding and affected revisions

The transfer trainer at `c371938b89eab48f5c8690d32d7d0c53d01a963b` uses the native Fairseq criterion's detached, label-smoothed Unit CE sum. The same producer is present at the PR #8 base `b6abf13a6bf8dd16dcd6c0fa1c99d6c5bfdbadfa`. The pinned Fairseq `3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99` returns unrounded `AverageMeter` values without unboxing tensors. The former transfer JSONL writer omitted those tensors and replaced missing `train/main_loss` with the rounded Unit NLL in bits multiplied by `ln(2)`. If NLL was itself missing, the fallback was zero. This affects the native KL, Annealed KL and Mask conditions using that producer, independently of the coefficient. The loss used for gradients did not take this path.

For a target token `y` and `V` classes, pinned Fairseq distributes the smoothing mass `ε` over the `V−1` other classes. Per-token CE in nats is `−(1−ε) ln p(y) − ε/(V−1) Σ[j≠y] ln p(j)`. Its floor is the entropy of that distribution, approximately 1.427 at `ε=0.2, V=104`. NLL is `−ln p(y)` and has no such floor. The reported transfer value near 0.95 is inconsistent with the CE floor under those assumptions. This is not a point-by-point comparison of the actual remote histories. The pinned reducer regression reproduces the dtype and fallback using real Fairseq and PyTorch.

Other verified defects were fabricated zeros for missing total loss or gradient norm, omission of tensor-valued diagnostics, averaging of categorical worst-layer indices across the Fairseq window, and the W&B fallback combining native and Fairseq-window alignment rows under the same metric names. The former `train/clip_fraction` used Fairseq's 0–100 statistic. The corrected window clip fraction uses 0–1. Native curve exports now use measured CE and optimization loss and convert Dev Unit CE to nats for the display.

## Metric definitions

`N_i` is the native main `sample_size` of microbatch `i` (target-unit tokens for the registered recipe). `R_i,l` is the number of teacher rows with positive mass after source padding exclusion. `N=Σ_i N_i`. A logical update uses the successful Fairseq training step after any overflow retries. Fairseq `train_inner` windows cover the updates since Fairseq reset those meters and use the weights given below. Dev refers to the complete prepared Dev split. Native JSONL records every successful update and every scheduled full-Dev selection respectively. W&B samples native training at update 1, each multiple of 100, and the currently published checkpoint when measured. Fairseq train rows are admitted only at recorded log points at update 1 or multiples of 100; all recorded Dev rows are eligible. All step coordinates use completed optimizer updates.

| Metric | Definition and weighting | Source and W&B name |
| --- | --- | --- |
| Unit CE | Sum of pinned label-smoothed Unit CE divided by `N`, nats per main target token. | Native v2 `train/unit_ce_nats`. The historical Fairseq CE meter `train/main_loss` is `train/window/main_loss_fairseq`, weighted by `N` across updates. |
| Unit NLL and perplexity | Unit NLL sum divided by the number of main target tokens. Fairseq's NLL display divides by `ln(2)` and perplexity is `2^NLL(bits)`. | Native v2 `train/update/unit_nll_nats`; `train/window/nll_loss` and `train/window/perplexity` where printed. |
| Weighted task and optimization loss | The stock `speech_to_unit` task loss includes main CE and the three Fairseq-weighted auxiliaries. The optimization loss adds `Σ_i N_i λ_i L_align,i`. Both are divided by `N` in native telemetry. | `alignment/update/task_loss` and `train/update/optimization_loss_nats`. Fairseq logs `alignment/window/task_loss` in nats and `train/window/loss_fairseq` in bits with Fairseq display precision. |
| Source Letter, Target Letter and decoder-target CTC | Each raw auxiliary loss sum is divided by its own native auxiliary sample-size sum and `ln(2)`. The window meters use that auxiliary sample size. `loss_weight` entries are Fairseq's latest recipe weights. | `train/window/multitask_*`; `dev/full/multitask_*`. The registered recipe weights are 8, 8 and 1.6. |
| Dev Unit CE and total | Native exact Unit CE sum divided by full-Dev main sample size and `ln(2)`. Fairseq also emits weighted task total and NLL in bits, perplexity, and the CE diagnostic in nats when present. No teacher enters Dev evaluation. | `dev/main_loss` retains its meaning and history. Reported Fairseq values use `dev/full/*`. |
| KL | `Σ_s P_teacher(s) (ln P_teacher(s) − ln P_student(s))`, in nats, after source padding handling and distribution normalization. Zero-mass teacher rows are excluded. Each layer means its `R_i,l` valid rows. `kl_mean`/`kl_worst` are the mean/max of the valid layer means per microbatch. | `alignment/update/kl_layer_*`, `kl_mean`, `kl_worst`; separate `alignment/window/*`. |
| Layer loss, weight and alignment loss | `D_l` is KL for KL conditions and `1−region_mass` for Mask. The microbatch aggregate is the τ-scaled log-mean-exp over valid layers and `w_l` is its softmax derivative. The logged weighted loss is the actual `λ_i L_align,i` passed to the native task loss. | `alignment/update/D_*`, `w_*`, `loss`, `weighted_loss`. Named window counterparts stay separate. |
| Entropy and Mask region | Entropy is `−Σ p ln p` over allowed source positions, averaged over valid rows then valid layers. Mask uses the smallest positive teacher-probability set reaching `top_p`, with stable source-index ties. Region mass is Student mass inside it; coverage is selected frames divided by allowed frames, averaged over valid rows. | `alignment/{update,window}/{teacher_entropy,student_entropy,region_mass_*,coverage_*,top_p}`. |
| Valid rows and selected frames | Sum the corresponding counts over microbatches. `selected_frames_l` sums selected positions across valid rows. Fairseq's existing window meter reports a mean of these per-update totals. | `alignment/update/{valid_rows_*,selected_frames_*}` and `alignment/window/{valid_rows_*,selected_frames_*}`. |
| Alignment reduction across microbatches | Diagnostics above other than the two count families are weighted by `N_i`, the same weighting as the task objective. Invalid-layer row-level statistics contribute an internal zero when that layer is absent in a microbatch; valid counts document support. The weight is not pooled `R_i,l`. | The update values are exact for the specified statistic. Window means use Fairseq's `N` weighting except the count families. |
| Worst Layer | Argmax over the `N_i`-weighted `D_l`, excluding layers without any valid rows. Ties use the lowest layer index (0-indexed). `worst_layer_fraction_l = Σ_i N_i × 1[microbatch argmax=l] / N`. Window argmax is independently computed from logged window `D_l` and measured valid counts. | `alignment/update/{worst_layer,worst_layer_fraction_*}`. `alignment/window/worst_layer` requires sufficient layer evidence. Legacy averaged layer IDs are excluded. |
| Schedule | Actual λ at the model's pre-update index, τ, and Top-p. The logical row is attached to the update that just completed. Annealing progress and task-only phase use the configured 400k budget and the existing cutoff. The cutoff field is omitted until reached. | `alignment/update/{lambda,tau,annealing_progress,task_only_phase,task_only_start,top_p}`. Window means of phase/progress are separate; a window cutoff is undefined. |
| LR, grad norm and clipping | Native post-update scheduler rate, pre-clipping gradient L2 norm, and binary clipping event when clipping is configured. Fairseq averages the window norm and clip fraction over its observations. | `train/update/{learning_rate,gradient_norm,clip_applied}`; `train/window/{gradient_norm,clip_fraction}`. |
| Scaling, retries and time | Native FP16 scaler value after the successful step. Count of confirmed pre-optimizer overflows for that logical step on the adapter's retry path; omitted when that instrumentation is unavailable. Fairseq window scale and OOM statistics retain their original definitions. Time is Fairseq cumulative training wall-clock seconds across resumes. | `train/update/{loss_scale,overflow_retries,seconds}`, `train/window/{loss_scale,oom}`. `update` comes from Fairseq's optimizer counter, `train/max_update` from the maximum verified durable progress and prior Summary. |
| Aux-BLEU, ASR-BLEU and failures | Fixed Dev 500 for target-letter decoding and 100 for unit → vocoder → ASR. English normalization, SacreBLEU 13a, and all selected references in the denominator. Recognized generation failures use empty hypotheses; infrastructure errors publish no result. | `eval/{aux_bleu,asr_bleu,aux_failures,asr_failures}`. `result.json` records sample counts, pair IDs, policy, hashes and the exact checkpoint update. |

The logical recorder detaches and unboxes only finite numeric scalars, including zero-dimensional tensors. Missing, non-finite, boolean and non-scalar values are omitted. The numeric zero is preserved. The JSONL rows have `metric_schema: 2`. Dev and BLEU files retain their existing formats and metric definitions. The standard Fairseq parser can recover finite values represented as numeric strings. Snapshot receipts and process-plan identity checks limit both stream types to the matching published checkpoint. ## Historical migration

- **Already measured** include checkpointed native Dev Unit CE, verified BLEU artifacts, and safe native v1 logical alignment diagnostics, LR and elapsed time where present. The new live reporter can publish safe logical values under the corrected names.
- **Recoverable from Fairseq logs** include displayed CE, NLL, perplexity, auxiliaries, alignment statistics and the optimizer diagnostics in the table. Keep them in `train/window/*`, `alignment/window/*` or `dev/full/*`, preserving the printed precision. Their source log must match the command and contract and show its own durable checkpoint progress.
- **No exact reconstruction** for historical per-update CE where v1 stored a fallback, omitted tensor diagnostics where the sole surviving value is a window statistic, fabricated zero gradients, or values from unpublished progress. Existing `train/main_loss` and unscoped legacy alignment history remain in W&B. Exclude that legacy `train/main_loss` from matched CE comparisons.

Baseline benchmark PR #1 already imports verified per-update Unit CE in nats as `train/main_loss`. Keep that history and Run ID. The schema-v2 mapping covers Unit CE, weighted Task Loss, LR, Dev Total and the three Dev auxiliary losses. [Benchmark PR #1](https://github.com/Yaaamashiro/ja-en-direct-s2st-benchmark/pull/1) · [Baseline schema-v2 mapping and matched BLEU protocol](WANDB_BASELINE_COMPARISON.md)

This change keeps the contract-derived Run IDs and uses distinct series. Explicit backfill scans uncached, unsampled W&B history and compares each `(update, metric key)`. A matching point is skipped, and a partial row gets only its missing keys. A differing value stops the operation before a writer opens. Appended rows retain the original `update` and use W&B's increasing internal step. The normal live reporter continues to use monotonic stream watermarks. Explicit backfill with a current local ownership receipt resumes the idle Run with `resume="must"`. Use the Colab recovery cell if the receipt is missing. It supports explicit manual recovery for unbound Runs and the matching shared bucket for GCS-bound Runs. [CPU writer recovery](WANDB_RECOVERY.md#restore-writer-ownership-on-a-cpu-runtime)

## Colab

Keep the original run settings, Drive paths, experiment ID and contract. Before switching code, wait for `durable_updates` and a published snapshot receipt and ZIP. Stop the selected training cell and preserve the runtime's `execution` folder. Follow the pinned release procedure in [W&B recovery](WANDB_RECOVERY.md). For normal resumed training the new reporter sends the schema-v2 series and saved BLEU to the same Run. A separate sync uses CPU and needs no trainer or model evaluation.

Both audit and sync select the matching published ZIP and verify the SHA-256 of `native-run.json` and each declared `alignment-train.jsonl` and `native-dev.jsonl` member against `snapshot.json`. Only these members are copied to temporary local storage. This is member verification against the published receipt; the checkpoint payload and whole-archive SHA-256 are not read. Local copies of the JSONL are not used. A member declared in the receipt must exist exactly once with the matching hash. A JSONL absent from the receipt is treated as unavailable. `--work` identifies the original stage path recorded in the receipt, even on a cold runtime where it does not exist. The archive plan supplies the training contract; `--contract` can pin the expected hash explicitly.

Use the notebook's existing helpers to audit or backfill a selected condition. Audit opens no W&B connection and needs only standard-library Python. It reports legacy values and aligned Fairseq-window values as separate columns. Equality with a multi-update NLL window alone does not establish a historical per-update value.

```python
method = 'distillation'
work = RESEARCH_ROOT / method
backup = Path(PERSISTENT) / 'stages' / ('research-v3-' + method + SCOPE_SUFFIX)
command = [REPO / 'tools/wandb_transfer.py', '--work', work, '--backup', backup,

           '--entity', 'yaaamashiro-national-institute-of-technology-okinawa-college']
execute(PYTHON, *command, '--audit-metrics-only', name='wandb-audit-' + method)

tracking = prepare_wandb()
if tracking is not None:
    python, key = tracking
    execute(python, *command, '--sync-metrics-only', name='wandb-metric-backfill-' + method,
            env=dict(os.environ, WANDB_API_KEY=key, WANDB_WRITER_BUCKET=WANDB_WRITER_BUCKET.strip(),
                     AT_LOG_WANDB_DRAIN='1'))
```

For saved BLEU use the existing [BLEU-only sync](TRANSFER_BLEU.md#sync-scores-already-on-drive). Neither sync requires retraining or model loading. Fairseq windows require the original execution logs or a retained copy with matching command, plan and durable progress receipts. Those process logs use their existing provenance checks and are separate from the verified archived JSONL members. An independent W&B writer still needs the ownership handoff above. Native loss, optimizer, FP16 retry policy, annealing, and checkpoint selection are separate from this migration. The exact reviewed telemetry patch maps to the prior native S2UT implementation identity so old checkpoints and calibration bindings remain usable.

## Verification

- Python 3.10.22, PyTorch 2.7.1 CPU and pinned Fairseq reproduced the old Tensor filtering and rounded-NLL fallback. Unequal microbatch tests checked label smoothing, `ln(2)` conversion, missing values, measured zeros, layer argmax and worst-layer fractions.
- Fixed-input native CPU comparisons passed for zero-weight transfer versus the stock trainer, stop and restore under all three methods, and confirmed FP16 overflow control using a simulated scaler. A separate nonzero-KL check compared the released criterion and Trainer hooks against their revised versions on the same two microbatches. Losses, gradients, parameters, optimizer, scheduler, update counter and Torch RNG matched exactly.
- W&B 0.31.0 offline output retained increasing internal steps for earlier BLEU `update` coordinates. Mocked online sync covered historical holes, interrupted submission, identical Run IDs, duplicate prevention and active-run refusal. The compatible scientific source map matched the full released tree for the reviewed patch in LF and CRLF and rejected an unreviewed edit. Notebook release checks and wheel build passed.
- No production W&B write, live history comparison, CUDA/Colab training test, full production checkpoint restore, or new BLEU evaluation was performed in this audit.
