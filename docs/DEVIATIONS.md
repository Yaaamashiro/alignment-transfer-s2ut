# Deviations and implementation definitions

1. **Reference training.** The primary comparison uses the pinned native fairseq and benchmark S2UT model, auxiliary losses, optimizer, scheduler, precision, logical batches, budget, and selection policy. The alignment task, model, and criterion are local extensions.
2. **Loss-only transfer.** The main CLI and notebooks use KL-based Attention Distillation, Annealed KL-based Attention Distillation, and Attention-level Knowledge Distillation. The standalone legacy workflows retain Guidance, Annealed Guidance, Monotonic, and beta and smoothing settings for historical regression checks.
3. **Worst-layer microbatch definition.** Apply LogSumExp to each training microbatch, then let the native Trainer accumulate gradients by sample size across the logical batch. [Method](METHOD.md)
4. **Calibration.** Replay a fixed training subset for two passes from the same fresh initialization and measure τ and gradient norms with zero optimizer updates. KL and Mask use separate coefficients, target gradient ratio 0.5, worst-to-median ratio 3, and 16 logical batches. τ candidates come from individual microbatches, and λ uses logical-batch gradient norms. FP16 calibration qualifies a single fixed backward scale across Task, KL, and Mask. It widens gradients to FP32 before unscale and accumulation. The native training optimizer retains dynamic scaling. Missing precision evidence or undefined coefficients stop calibration. [FP16 recalibration](CALIBRATION_PRECISION.md)
5. **Teacher provenance.** Reuse all-layer extraction, character and subword spans, source and target projection, all-head averaging, and the packet format. Text-only attention binds to text identity. CTC, units, the teacher, and S2UT bind to speech identity. Keep the original artifacts for reuse.
6. **Persistence.** Work and frequent logs stay on the VM. The pinned runtime publishes verified ZIPs to Drive, including the alignment logs. The plan and checkpoint bind the calibration artifact hash for resume.
7. **Diagnostics.** Log per-update layer losses and weights and provide a separate teacher-forced dev alignment diagnostic. Translation generation and validation run teacher-free. Attention is a learned signal.
8. **Limits.** CPU tiny tests and Windows sampler fixtures check connectivity. Colab preflight requires the compiled native sampler. Long runs on real data and BLEU improvements require separate validation.

9. **Configuration and terminology.** The canonical conditions YAML supplies the annealing fraction and schedule to the loss and logs. The tail is task-only, and validation and inference are teacher-free. Public labels map to the existing method IDs. FP16 transfer requires a matching precision-qualified calibration v3 artifact.

10. **Corpus input.** Select the corpus and manifest independently of the experiment ID. Preserve split, ID, and text and train the Baseline on train and dev. If QC information is present, accept only `accepted` rows. The adapter allows an empty test TSV in the pinned prepared-data validator. Check the speech pairs as a subset of the original T2TT text by ID, split, and content. The Kokoro release is an optional example. Older CLI names are compatibility entry points. Use the original ID and revision to resume old runs.

11. **S2UT audio loading.** Check prepared TSV audio paths against the ZIP index before training. The pinned benchmark Downloader verifies ZIPs and WAVs on demand, and fairseq prefetches the next batch in sample order. Only an exact SHA-256 match to an approved set of I/O-only source changes enables the `74c5efa` Baseline adapter and transfer implementation identities. [Validation records](VALIDATION.md)

12. **Transfer Pilot.** The native Trainer retains the full Baseline budget while an operational stop writes the last checkpoint. Transfer checkpoints also store fairseq's pending epoch scheduler transition, FP16 scaler counters, and FP32 optimizer master weights for exact continuation. The reviewed source hashes preserve the historical Baseline adapter identity. The transfer implementation retains its own hash and requires calibration against that implementation. [Native transfer pilot](PILOT.md)

13. **Explicit coefficients.** `--kl-lambda` selects the initial KL coefficient for KL and Annealed KL training. `--mask-lambda` independently selects Mask's coefficient. The notebook defaults are 1.0 and 10.0. Both τ values come from the verified calibration, which retains the original λ estimates. Omitting a coefficient uses its calibrated value. The resolved policy is used by the loss, diagnostics, and checkpoint metadata and changes the run contract. Existing calibration can cross only the exact reviewed coefficient-policy source transition. [Fixed coefficient workflow](FIXED_KL.md)
